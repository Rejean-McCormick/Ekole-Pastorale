# GitHub Wiki publication policy — not an automatic publisher

**Status:** local editorial policy created 2026-11-23, **not** a recovered `wiki/Publishing-the-GitHub-Wiki.md` page. This snapshot does not prove that a GitHub Wiki is active. **This repository does not publish the Wiki automatically.**

Before any public-facing Wiki action, the repository owner should:

1. Confirm whether an external GitHub Wiki exists and establish its canonical location and editors.
2. Audit each proposed page against the current code, course inventory (32/7), source Kristal workspaces, documentation links, and version-specific constraints.
3. Remove unsupported publication claims; keep the distinction between local derivation, app compatibility tests, ecclesial approval and permission for public/student exposure.
4. Obtain the required content, pedagogical, safeguarding and licensing reviews, including third-party citation and image rights.
5. Have an authorized maintainer review and explicitly approve each page and its final destination; retain a record of provenance and approvals before using GitHub's normal Wiki editing controls.
6. Recheck links and content after any *separately authorized* manual publication.

**Not allowed as a shortcut:** automatically publishing README contents or generated `pack.json` / `publications/eleve/` artifacts; treating a successful local test or overlay installation as publication permission; changing the neutral Ekole Core to introduce domain rules.

For historical mappings see [Wiki gaps](WIKI_GAPS.md), and for testing see [Local testing guide](TESTING_AND_VALIDATION.md).
